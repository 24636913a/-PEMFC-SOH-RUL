# Demo 3：两台电堆分别建模，避免直接套用另一台的衰减速度

这是一个可以离线运行、结果可以复现的教学例子。它回答的问题是：**当电池片数、载荷工况和衰减速度不同，怎样先统一健康量的口径，再让每台电堆用自己的历史估计寿命？**

随包已包含代码、模拟 CSV、运行结果和图。默认运行会读取已附的数据，不联网、不下载真实数据，也不重新生成或替换数据。

## 先区分模拟设定与实验事实

- `FC1_like` 和 `RealHyFC_like` 是**合成情景名称**，不是 FC1 或 RealHyFC 的实测文件。
- 本例人为指定 5 片与 10 片电池、SOH 下降速率 3∶1。不能把这些设置当作真实数据的核实结论。
- FC1-like 使用恒电流，RealHyFC-like 使用变化的电流密度。恒电流和恒功率是两种不同的试验条件。
- “4% 阈值”在这里专指相对参考电压**损失 4%**，即 `SOH = 0.96`；它不是电压剩 4%，也不是通用报废标准。
- “分别建模”是一种可检验的研究设计。是否能发表论文仍取决于问题、创新、实验和证据，不能由所谓“易/中/难”档位保证。

## 1. 一键运行

建议 Python 3.10 或更新版本。已验证环境记录在 `results/environment.json`。

```bash
python -m pip install -r requirements.txt
python run_demo.py
```

Windows 可以在解压后的目录打开 PowerShell，使用同样两条命令。若系统命令为 `python3`，把上面的 `python` 换为 `python3`。

可将结果写到新目录，保留随包的结果：

```bash
python run_demo.py --output-dir results_new
```

只有明确需要按 `config.json` 重新生成模拟数据时，才运行：

```bash
python run_demo.py --regenerate-data --data-dir data_new --output-dir results_new
```

`--regenerate-data` 会覆盖指定数据目录内对应的合成文件。固定随机种子可复现生成过程；默认入口不调用它。运行时间通常为数秒，无 GPU 或网络要求。

## 3. 算法的三个步骤

### 步骤 A：先除片数，再统一参考工况

串联电堆电压先转为平均单片电压：

`V_cell = V_stack / n_cells`

本例假设起始标定已独立测得局部极化斜率 `r` 和温度系数 `k_T`，将日常观测校正到固定电流密度和温度：

`V_ref = V_cell + r × (j − j_ref) − k_T × (T − T_ref)`

然后用每台电堆自己的初始参考电压计算：

`SOH = V_ref / V0_cell`

`V0_cell` 是预先获得的起始参考值。代码不会拿整段寿命的最大电压作为分母，也不会用最终寿命归一化时间。单片化可去掉片数造成的尺度差异；参考工况修正可去掉本例已建模的载荷和温度影响。它们都不能让两台电堆的老化速率自动相等。

本例对 `r`、`k_T` 的已知性和恒定性作了简化。真实应用必须通过独立标定或因果诊断估计这些参数，并检查老化后斜率变化、湿度/压力影响及恢复状态。不能用一条未校正的动态电压直接解释成健康度。

### 步骤 B：只在各自历史内拟合缓慢衰减

分别使用 `time_h <= train_end_h` 的数据拟合最小二乘直线：

`SOH(t) = a + b × (t − t_cut)`，约束 `b <= 0`。

这里的约束只施加在参考工况的长期健康模型上；日常原始电压可以随载荷或恢复上升。模型是透明的低复杂度基线，不是神经网络。

本例固定训练截点为 FC1-like 的 500 h、RealHyFC-like 的 1500 h。这是配置中的绝对时间，不是从真值阈值或最终寿命倒推的数据切分。训练后一次性预测其余时间；预测期间不吸收未来观测值。

三种方法的区别：

| 方法 | 下降斜率来自哪里 | 预测起点的健康水平 |
|---|---|---|
| `independent` | 本堆训练历史 | 本堆历史拟合的当前水平 |
| `pooled_common_rate` | 两堆训练历史，共享一个下降斜率并允许各堆不同截距 | 与独立模型完全相同 |
| `cross_stack_rate` | 另一台堆的训练历史 | 与独立模型完全相同 |

所有方法使用同一目标堆起点，比较的主要是**错误共用或移植衰减速度**造成的预测差异。跨堆对照已经允许用目标历史对齐当前健康水平，因此不会靠片数或起始截距的明显不匹配人为放大迁移错误。

共享斜率通过各堆内时间/健康量去均值后汇总最小二乘得到。由于时间仍以小时计，历史跨度更长的堆会有较大的斜率信息权重；这个对照不等同于所有可能的迁移学习方法。

### 步骤 C：用同一健康口径计算 RUL

在预测起点 `t_cut`，如果 `a > SOH_threshold` 且 `b < 0`：

`RUL = (SOH_threshold − a) / b`

若当前已低于阈值，RUL 为 0；若斜率被约束为 0 且尚未到阈值，则该直线模型下没有有限到达时间，输出空值。这个 RUL 对应参考工况的健康阈值，不是未来动态工况下瞬时最低电压的阈值。

模拟真值仅在预测全部完成后读取，用来评价误差。若真值记录末尾仍未到阈值，则标记 `right_censored`，记录下界，不把未知寿命错误记成 0。替换真实 CSV 时没有真值文件也能运行，只跳过真值 SOH 和真 RUL 的评价。

## 4. 如何替换成真实数据

把两个观测文件放入新目录，例如 `my_data`，文件名对应 `config.json` 中的两个 stack ID：

| CSV 字段 | 单位 / 含义 | 要求 |
|---|---|---|
| `time_h` | 累计运行小时 | 严格递增、不重复 |
| `stack_voltage_V` | 电堆总电压，V | 不能把单片电压误填在此处 |
| `current_density_A_cm2` | 电流密度，A/cm² | 不是总电流 A；需要已知活性面积换算 |
| `temperature_C` | 温度，℃ | 口径应与标定一致 |
| `n_cells` | 串联电池片数 | 与配置匹配、保持正值 |

同时在自定义配置中调整：每堆片数、`reference_cell_voltage_V`、绝对时间训练截点、参考工况、初始极化斜率和温度系数。

```bash
python run_demo.py --config my_config.json --data-dir my_data --output-dir my_results
```

没有 `*_truth.csv` 可以直接运行。若提供它，至少应有 `time_h,true_soh` 两列；仅用于事后评价，不输入模型。预测与真值按相同时间戳匹配，程序不会为评价悄悄用未来标签修正预测。真实数据中的跳变恢复、变斜率或工况遗漏需要先用相应模块处理；这里的简单线性模型不能替代完整的退化建模。

## 5. 自动验证与结果边界

每次运行都会执行有意义的自检，并保存 `results/checks.json`：

- 任意扰动训练截点之后的电压和电流，训练拟合与预测值均保持不变。
- 扰动另一台电堆的训练历史，本堆独立模型不变；跨堆迁移对照应随源堆变化。
- 更换虚假的真值评价数据，不修改已生成的预测。
- 更改模拟器的真退化速率、随机种子和仿真终点，已给定观测上的估计不变。
- 检查 RUL 的单位换算、平坦曲线、已达阈值以及右删失分支。
- 电压与串联片数同时乘以相同倍数，单片健康量保持一致。
- 模型预测的长期健康量非增。

此演示特意采用与线性模型一致的潜在衰减形式；因而独立模型表现良好只说明实现和教学逻辑成立，不代表真实电堆预测性能。真实研究仍需多次运行/多台设备、独立测试、非线性与分布变化验证，以及能检验覆盖率的预测区间。本例不输出未经校准的“置信区间”，也不把单次种子的效果称作统计显著。

## 6. 建议的课堂讲解顺序

1. 看图 01：原始电堆电压为何不能直接比较，动态负载为何引入波动。
2. 看图 02：单片化和工况修正后，斜率依然不同；固定当前水平再比较三条预测线。
3. 看图 03 和 `metrics.csv`：分别建模的误差、源堆速率直接迁移带来的 RUL 偏差。
4. 将配置中的两台模拟速率改为相同，并重新生成到一个新目录：观察共享模型是否仍然明显更差。这个反例说明结论依赖差异是否实际存在。
5. 将阈值改为更低值：观察真值记录未到阈值时的右删失处理。阈值变化不应改变已经训练好的斜率。
